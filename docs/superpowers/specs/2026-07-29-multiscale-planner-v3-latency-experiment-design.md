# 多尺度路径规划 v3 一秒指标实验设计

## 1. 目标

用一个可重复、不过度扩展的实验验证 C++20 `PlannerV3` 在十米级、百米级和千米级地图上的在线规划耗时。实验只评价自然完成后的端到端耗时，不设置 1 秒运行时截止，也不改变规划器、能力包或既有安全边界。

## 2. 实验矩阵

地图尺度固定为约 `12 m × 12 m`、`120 m × 80 m`、`1200 m × 200 m`，对应分辨率为 `0.5 m`、`2 m`、`5 m`。百米级和千米级地图表示环境—平台联合约束建模输出的认证任务栅格，不宣称具有局部落足或轮地接触级分辨率。每个尺度包含三个从双门槛 G1 `validation3` 冻结场景派生的确定性参考场景：

1. `G1_LOW_KNOWN`：参考 `validation/scenario-0027/standard-proxy/v1`，源场景哈希为 `564835143c269d1ef4fb8d01cb7517cf4efb674bb1554c36467a1d59eb39f16c`，源硬障碍代理比例为 `0.006683349609375`。
2. `G1_MEDIUM_KNOWN`：参考 `validation/scenario-0007/standard-proxy/v1`，源场景哈希为 `6f754169bb3c4837978e3e852258493f4b1c971e8a59148a9a8269fb306a95bc`，源硬障碍代理比例为 `0.01348876953125`。
3. `G1_HIGH_FRONTIER`：参考 `validation/scenario-0116/standard-proxy/v1`，源场景哈希为 `49e4254dc8e5602be67cc2e9eb68af65093ec049b463e3581edfc9b5f352b554`，源硬障碍代理比例为 `0.03814697265625`。该场景保留未知区；轮式和足式输出已知区安全前沿参考，飞跃式只在未知区边缘内侧的已知认证范围着陆。

三个参考场景在 C++ 中按冻结的 G1 proxy seed、障碍比例和密度等级生成尺度化岩块核心小簇，并保护起点与确定目标/着陆范围。派生合同固定为 `g1_validation_reference_scaled/v1`，障碍来源固定为 `synthetic_terrain_obstacle_proxy/v1`，且 `physical_obstacle_cells_written=false`。它们只用于构造 G1 风格的多尺度规划负载，不是精确 G1 场景重放，不复用 G1 覆盖率分母，也不能作为 G1 门槛通过证据。

每个场景分别运行轮式、足式和纯弹道飞跃式规划器，共 27 个“尺度 × 场景 × 平台”组合。轮式与足式的代表规划距离约为 8 m、80 m、500 m；飞跃式仍只输出下一次可执行飞跃，目标距离约为 4 m、8 m、10 m，不把地图尺度误写成单跳能力。百米级和千米级地面规划可使用 4–10 m 的预认证宏运动基元，但持续时间必须满足原速度上限，且扫掠验证覆盖完整宏段。

环境层包含已知掩码、高程、法向、坡度、粗糙度、硬障碍、置信度和静态速度限制。规划器使用相同环境层与各平台认证能力包共同生成平台相关安全投影，因此图中的可行域是环境—平台联合约束结果，而不是仅绘制障碍物。飞跃平台不具备地面安全前沿停车语义，所以实验不伪造 `SAFE_FRONTIER` 能力。

## 3. 重复次数与计时边界

每个组合：

- 独立构造场景、请求、能力包和 `PlannerV3`；
- 记录 1 次冷启动，仅作补充数据；
- 预热 3 次，不进入主统计；
- 正式重复规划 30 次。

正式样本总数为 `3 × 3 × 3 × 30 = 810`。每次计时从调用 `PlannerV3::Plan()` 前开始，到 `PlanningResponse` JSON 序列化完成后结束；地图生成、文件 I/O 和出图不计入。所有调用自然完成后才判断指标。

## 4. 统计与通过条件

对每个场景、每个尺度及每个平台直接从原始正式样本计算：

- 正确结果率；
- P50；
- P95；
- 最大耗时。

`G1_LOW_KNOWN` 和 `G1_MEDIUM_KNOWN` 的正确结果为可激活的新参考；`G1_HIGH_FRONTIER` 中轮式和足式的正确结果为安全前沿参考，飞跃式的正确结果为已知区内认证着陆范围的新参考。主通过条件为：

1. 810 次正式调用的结果类型均符合对应场景预期；
2. 每个平台在全部尺度、全部场景合并后的端到端 P95 严格小于 1000 ms；
3. 同时报告各“尺度 × 平台”的 P95，避免总体统计掩盖千米级退化。

1 秒只是一条实验评价线，不参与规划终止、资源截止或结果选择。

## 5. 交付物

实验运行器输出到 `D:/xunce/out/planner-v3-multiscale/`：

- `manifest.json`：实验配置、构建和机器信息；
- `latency-samples.jsonl`：810 条正式样本及冷启动记录；
- `summary.json`：场景级、尺度级和平台级统计；
- `responses.jsonl`：每个组合一条代表性响应与路径绘图数据。

离线 Python 脚本只读取上述文件并生成：

1. `scenario-overview.png`：3 × 3 多尺度场景图，显示地形、联合不可行区、起点、目标/前沿以及三平台代表参考；飞跃式显示弹道弧线与着陆范围。
2. `latency-results.png`：按尺度和平台显示 P50、P95、最大值、正确结果率及 1000 ms 指标线，耗时轴使用对数尺度。

出图脚本不进入 C++ 规划热路径。实验只新增场景夹具、基准运行器和离线出图，不修改默认策略、不连接执行器、不发布 checkpoint、不启动 canary。

## 6. 最小验证

只做与本实验直接相关的检查：

- 新场景夹具能生成三个尺度、三个场景且联合约束层尺寸一致；
- 运行器确实完成 810 次正式调用并按原始样本计算 P95；
- 两张 PNG 能生成且尺寸非零；
- Release 模式执行一次正式实验。

不增加无关回归矩阵、代码审查轮次或算法性能扩展试验。
